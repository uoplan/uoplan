     Plan: Explore Search Redesign

     Context

     The explore home page currently has a centered hero with a search bar,
     subtitle, and spotlight gallery. Results render in-page as a vertical list
     replacing the gallery. The redesign moves the search bar to the top-left of
      the home page, removes the subtitle and spotlight gallery, and routes to a
      new /search?q=... page as the user types. That page shows Spotify-style
     horizontal card sections for Courses and Professors, each with rich
     grade/rating data. Disciplines are a future step.

     ---
     Steps

     1. Augment search entries with grade viz data

     File: apps/web/src/lib/explore/gradesSearch.ts

     - Add gradeViz: GradeVizData | null to ExploreCourseSearchEntry and
     ExploreProfessorSearchEntry
     - In buildCourseSearchEntries: group offerings by normCode, call
     mergeGradeDistributionCounts to get a merged distribution, pass to
     buildGradeVizData (from packages/schedule/src/gradeDistribution.ts)
     - In buildExploreProfessorSearchEntries: same but group by groupId
     - Import buildGradeVizData from schedule — verify this function exists; if
     not, check gradeDistribution.ts for the correct export name

     2. Add /search route

     New files:
     - apps/web/src/routes/search/route.tsx — layout route wrapping with
     AppDataRouteGate + ExploreHistoryProvider (same pattern as
     explore/route.tsx)
     - apps/web/src/routes/search/index.tsx — defines Route = 
     createFileRoute('/search/') with validateSearch: z.object({ q: 
     z.string().default('') }), renders <SearchResultsPage />

     3. Build SearchResultCourseCard

     New file: apps/web/src/components/explore/SearchResultCourseCard.tsx

     Card contents (dark card, ~200px wide, fixed height ~180px):
     - Course code (bold, top)
     - Course title (dimmed, truncated 2 lines)
     - GradeDistributionBottomBar at the bottom of the card
     - Most common grade (derived from gradeViz.histogram) + % passing inline
     stat
     - No grade data → show a subtle empty state within the card

     4. Build SearchResultProfessorCard

     New file: apps/web/src/components/explore/SearchResultProfessorCard.tsx

     Card contents:
     - Professor name (bold)
     - RMP rating (e.g. ★ 3.8 · 42 ratings) or dimmed "No rating" if absent
     - Course count (N courses)
     - GradeDistributionBottomBar + most common grade if gradeViz available

     5. Build SearchResultsPage

     New file: apps/web/src/components/explore/SearchResultsPage.tsx

     Props: catalogue, terms, professorRatings, search param q

     Layout:
     - Search bar at top-left (reuse ExploreSearchInput, top-aligned, not
     centered)
     - Two horizontal scroll sections below (Spotify-style):
       - Section header ("Courses" / "Professors") — label + count
       - overflow-x: auto, cards laid out in a single row with gap
       - On mobile: same horizontal scroll (no stacking)
     - Section ordering: mirror existing professorsFirst logic from
     useExploreSearch
     - Empty/loading states handled inline

     Hook: create useSearchPageSearch (or extend useExploreSearch) that:
     - Reads initial q from route search params
     - Maintains local draft query state; debounces → calls searchExplore
     - On change, updates URL via navigate({ search: { q } }) (replace, not
     push)
     - Returns results, resultsStale, draftQuery, setDraftQuery

     6. Redesign ExploreSearchPage (home)

     File: apps/web/src/components/explore/ExploreSearchPage.tsx

     - Remove subtitle (explore.subtitle)
     - Remove spotlight gallery and all spotlight-related logic/imports
     - Move search bar from centered max-width-584 stack to top-left aligned
     layout
     - Title stays but left-aligned
     - onChange on the search bar calls navigate({ to: '/search/', search: { q: 
     value } }) — no in-page results shown
     - Strip out showSearchResults, ExploreSearchResults, useExploreSearch usage
      from the home page

     7. Animation

     On /explore/: When the user types, navigate immediately. No fade — use a y:
      -12 slide-up exit on the search area via Framer Motion.

     On /search/: Page enters with initial={{ y: 20 }} → animate={{ y: 0 }}
     (translate only, opacity stays 1 throughout) so it slides in without a
     fade.

     8. i18n

     Add new message keys to both en/messages.po and fr-CA/messages.po:
     - search.resultsCourses — "Courses" / "Cours"
     - search.resultsProfessors — "Professors" / "Professeurs"
     - search.noResults — "No results for …" / "Aucun résultat pour …"
     - search.courseCount — {count} courses / {count} cours

     9. Docs

     Update or create docs/explore-search.md covering the new /search route,
     card components, and grade-data augmentation. Update docs/README.md.
